## 2026-11-16 — Confirmed TDS, PI correction and GSTIN verification rules

- **Manual TDS only.** PI creation and the authorized one-time correction accept an exact manual TDS amount (default zero); no percentage is inferred or calculated. Gross PI value, manual TDS and net receivable are persisted in paise and shown separately in preview, PDF, DOCX, XLSX, dashboards, PI register and exports. Outstanding/payment limits use net receivable. TDS is never counted as a verified cash collection.
- **Exactly one same-number issued PI correction.** The PI owner or Admin may create one separate corrected snapshot for an issued Proforma Invoice, with a mandatory reason and the exact original PI number. The original snapshot is never rewritten, no new number is consumed, a second correction is rejected, and pending/verified allocations block correction. Active reports, messages and customer downloads use the effective corrected snapshot; Admin can download the original for audit. This workflow rejects non-Proforma/statutory documents.
- **Official GST portal assisted verification.** Client create/edit performs local GSTIN format/checksum validation and provides a secure new-tab link to `https://services.gst.gov.in/services/searchtp`. The human completes CAPTCHA/search and explicitly confirms the legal name, trade name, registration status and address. Source URL, timestamp and verifying user are stored; changing GSTIN/address clears stale verification. No scraping, CAPTCHA bypass or undocumented endpoint is used.

## 2026-11-16 — Sales & collections workflow (Admin / Employee)

- **Two roles only.** Admin (Shiv, Namit Sir, Admin) sees and manages everything. Employees (Jagriti, Soumo, Khushboo, Vaibhav, Nashra, Shivam, Zoya, Danish, Sanjay, Futurex) see only their own clients, PIs, payments, reminders and reports — enforced in every server query and export, not just the UI. Staff sign in with a short login ID (`jagriti`), stored as `<id>@futurex.local` (`LOGIN_ID_DOMAIN`). Logins were created with `scripts/provision-team.ts`; passwords were written once to the private `TEAM-LOGINS-CONFIDENTIAL.txt` at the project root (delete after distribution). Admin can rename, reset passwords, change role and disable users; everyone can change their own password under My account.
- **Payment entry → approval.** Employees record payments against their own issued PI (mode NEFT/RTGS/IMPS/UPI/cheque/cash/card/wire, date, UTR, remarks, optional PDF/JPG/PNG/WEBP proof ≤ 4 MB validated by file signature and stored privately). Entries start as *Pending approval* and never reduce outstanding. Admin approves (optionally emailing the client a payment-received confirmation) or declines with a reason. The employee sees the reason, corrects and resubmits (back to Pending), or withdraws a wrong entry. Every step (submitted, declined, corrected/resubmitted with before/after values, approved, withdrawn, proof added) is in the audit trail and shown as history on the entry. Amounts above the open balance (total − approved − pending) are refused; duplicate UTR+amount is refused.
- **PI cancellation.** Owner or Admin can cancel (void) a PI with a reason; blocked while it has approved or pending payments. The number stays reserved forever.
- **PI numbering.** One active series per document type; issuance picks it automatically. The counter is an atomic row update inside a SERIALIZABLE transaction with automatic retry, so simultaneous issuers get unique, consecutive numbers (25-way DB test + 8 simultaneous issues through the live API → 010…017). A rolled-back issue does not consume a number. Admin can change prefix/next number/padding from Administration; the change applies to the very next PI and cannot go back onto an issued or cancelled number. Dashboard warns Admin when the active series' FY differs from the current FY.
- **Dashboards & reports.** Employee and Admin dashboards (period chips, sales, approved collections, outstanding, awaiting approval, declined, exhibition breakdown, highest balances). Reports: Employee performance (Admin only), Exhibition-, Client- and Month-wise, PI register, Payment register — with IST period presets (today … quarter, FY half, FY, calendar year, custom), multi-employee, multi-exhibition, search, payment-state and payment-status filters, and Excel/PDF/CSV export of exactly what is on screen. Exports are audit-logged.
- **Reminders.** Personalised outstanding-balance reminders (single, selected, or all due) with balance, received amount, exhibition details, bank details, the employee as contact, an optional personal note and the PI PDF. Clients never see each other's addresses; already-reminded (20 h), fully paid and no-email PIs are skipped; every send is logged.
